# Voice PE Realtime 0.19.1 — explain mode for the household agent

Add-on version `0.19.1`, 2026-10-15. Builds on the
[0.19.0 router mode](0.19.0.md); applies only under `voice_runtime: live`
with router mode on and an agent bridge configured. Full entry in the
[changelog](../../openai_realtime_voice_agent/CHANGELOG.md).

## In one paragraph

"Can you explain how our bridge supports remote access?" is research, not a
quick lookup. The router backend now sends such questions to the agent as a
read-only explanation (`ask_openclaw` with `mode: "explain"`): the voice
acknowledges at once, by name when it knows the speaker, says it will get back
to you and offers a text summary instead. The answer comes back by voice,
read in full, in the open conversation or a short new session. Say "text
would be great" and it arrives as a short text (at most three sentences)
through the bridge's verified iMessage sender instead. A follow-up within half
an hour continues the same agent session.

## What changes

- **Explain route.** The backend picks it for questions about how the owner's
  own software, projects or systems work; the request carries a read-only
  research brief (change nothing, send nothing), a 10-minute budget and a
  session key that follow-ups reuse. One explanation runs at a time.
- **One acknowledgement.** Rotating phrasings; when the route outlives the soft
  budget it replaces the generic "still working" line, so at most the fallback
  clip and one acknowledgement are heard.
- **Delivery.** Voice by default, read to the end: a result being spoken holds
  its session until it has been heard, and a session closing under it hands
  the result to the next route instead of losing it. `deliver_by_text` (the
  "text would be great" tool) switches the task to a text for the recognised
  speaker; the bridge resolves the recipient, so `live_task_imessage_to` is now
  only an optional override. An explanation that was spoken is never texted
  as well.
- **Bridge contract.** `mode`, `budget_s`, `notification_recipient`; the agent
  replies with `SPOKEN:` and `TEXT:` parts; `/announce` and `/task-result`
  accept `ok` and `detail`. The reference bridge
  (`examples/openclaw-bridge/bridge.mjs`) implements all of it. See
  [agent integration](../agent-integration.md).

## Compatibility

Backward compatible. Requests without `mode` are unchanged, a bridge that does
not know explain mode simply answers as before, and the Realtime runtime is
untouched. No new option is required; firmware 1.3.1 is unchanged.
