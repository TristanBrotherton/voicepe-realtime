# Voice PE Realtime 0.19.2 — answers heard to the end, conversations with the agent

Add-on version `0.19.2`, 2026-10-15. Builds on [0.19.1](0.19.1.md); applies
under `voice_runtime: live` with router mode on. Full entry in the
[changelog](../../openai_realtime_voice_agent/CHANGELOG.md).

## In one paragraph

Two things that explain mode introduced in 0.19.1 now apply to ordinary
answers too. A background result the voice is given — a slow lookup, a late
action report, an agent answer — holds the session while it is being spoken,
so it is heard to the end rather than cut by the follow-up window; the hold is
bounded to the speech itself and the session's own maximum, and adds no idle
time. And the agent bridge keeps a conversation: the add-on's per-request
session key is honoured for ordinary questions and reused for follow-ups
within half an hour, so a second question continues where the first left off,
while the bridge drops its "be thorough" directive when the add-on already
asked for an answer-only reply.

## What changes

- **Heard to the end.** `_task_deliver_session` finishes a spoken result only
  once audible output has ended in a session that stayed open; meanwhile the
  task counts as pending for the session gate (`router_pending`). A session
  that closes under it re-queues the result for the next route (a reopened
  session, an announcement).
- **Session keys.** `request_session_key` now returns the device's current
  conversation key for 30 minutes (`CONVERSATION_FOLLOWUP_S`), minting a fresh
  one only while a request is still in flight on it (never two runs on one
  OpenClaw session). The reference bridge (`examples/openclaw-bridge`) honours
  a well-formed `session_key` that is not running and otherwise keeps its own
  per-room session; with `answer_only` it drops the THOROUGH-lookup line.
- **Reference bridge.** A late answer announced after the sync window carries
  `ok: true` (its error announce `ok: false`), so the add-on delivers it as a
  verified result rather than a request that was not completed.
- **Compatibility.** A bridge that ignores `session_key` behaves exactly as
  before; an add-on that sends none gets the bridge's per-room session.

## Fixed

- **One acknowledgement.** A result arriving while the fallback clip was still
  being sent released the voice's own "One moment" after it; the voice's
  pre-result speech is now held from the clip's start.
- **Local recognition.** The Home Assistant intent socket's lock could stay
  taken, routing every later command through the backend; it can no longer
  leak, and a stuck one is replaced.
- **Entities without a device class.** A supplied `device_class` is dropped
  for an entity that has none (an `input_boolean` "switch").
- **Room conversation.** After a false wake, talk in the room closes the
  session silently (four merged fragments past 160 characters, or a second
  utterance with no request within 90 s); only a wake word opens the next one.

## Verification

Workshop real-audio trials (see the private rollout notes): an ordinary agent
question followed by a follow-up that depended on the first (context kept,
short answer), a slow lookup heard to the end, the Test Switch on and off,
list additions with the fallback clip (one acknowledgement each), and a spoken
monologue after a wake (one "didn't catch that", then a silent close).
